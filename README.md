# Трекер привычек (Android)

Учебный проект «Разработка мобильного приложения по ТЗ» — **ТЗ №1: Трекер привычек**.
Платформа: Android, Kotlin + Jetpack Compose. Архитектура: MVVM + Repository.

Приложение позволяет вести список ежедневных привычек, отмечать выполнение, следить за
«серией» (streak) дней подряд, смотреть статистику и получать ежедневные напоминания.

## Функциональность (по ТЗ)

| Требование ТЗ | Реализация |
|---|---|
| CRUD привычек | Создание, просмотр, редактирование, удаление (с подтверждением) |
| Streak-счётчик | Текущая и лучшая серия, `domain/StreakCalculator.kt` |
| Локальная БД | Room: таблицы `habits` и `completions` (внешний ключ, каскадное удаление) |
| Уведомления | WorkManager: ежедневное напоминание в выбранное время, пропускается, если привычка уже выполнена |
| Пустые состояния | Пустой список с кнопкой «Добавить привычку» |
| Обработка ошибок | Валидация формы, Snackbar при сбоях БД, состояние «не найдено» |
| Загрузка | Индикатор на всех экранах, пока данные читаются из БД |
| Тёмная тема | Светлая/тёмная цветовые схемы по системной настройке |
| Юнит-тесты | 20 тестов на ключевую логику (серии, статистика, валидация, время напоминаний) |

## Экраны

1. **Список привычек** — карточки с серией, чекбокс «выполнено сегодня», счётчик «выполнено N из M», FAB.
2. **Создание / редактирование** — название, описание, напоминание (переключатель + время), удаление.
3. **Детали привычки** — текущая/лучшая серия, всего выполнено, % за 30 дней, календарь за 28 дней
   (нажатие на день меняет отметку — можно исправить пропущенный день).

## Архитектура

```
app/src/main/java/com/example/habittracker/
├── data/            Room: Entity, DAO, Database, HabitRepository
├── domain/          Habit, HabitStats, StreakCalculator, HabitValidator (чистый Kotlin, без Android)
├── notifications/   ReminderScheduler (WorkManager), ReminderWorker, ReminderTime
├── ui/
│   ├── list/        HabitListScreen + HabitListViewModel
│   ├── edit/        HabitEditScreen + HabitEditViewModel
│   ├── detail/      HabitDetailScreen + HabitDetailViewModel
│   ├── navigation/  Navigation Compose
│   └── theme/       Material 3, light/dark
├── HabitApp.kt      Application + простой ручной DI-контейнер
└── MainActivity.kt
```

Поток данных: `Room (Flow) → Repository → ViewModel (StateFlow<UiState>) → Compose`.
События пользователя идут в обратную сторону через методы ViewModel. Бизнес-логика серий и
статистики вынесена в `domain` и не зависит от Android, поэтому покрыта быстрыми JVM-тестами.

Выбор технологий: Room — по требованию ТЗ; WorkManager — переживает перезагрузку устройства и
не требует разрешения на точные будильники; ручной DI — для проекта такого размера Hilt избыточен.

## Сборка и запуск

Требуется Android Studio (Ladybug или новее) и JDK 17.

1. Откройте папку проекта в Android Studio, дождитесь синхронизации Gradle.
2. Выберите эмулятор (API 26+) или устройство и нажмите **Run**.

Из командной строки:

```bash
./gradlew testDebugUnitTest     # юнит-тесты
./gradlew assembleDebug         # APK: app/build/outputs/apk/debug/app-debug.apk
```

**APK через GitHub Actions.** После `git push` в ветку `main` workflow `.github/workflows/android.yml`
прогоняет тесты и собирает APK; скачайте его в разделе Actions → последний запуск → Artifacts.

Минимальная версия Android: 8.0 (API 26). Целевая: 15 (API 35).

## Уведомления

На Android 13+ при первом включении напоминания приложение запрашивает разрешение
`POST_NOTIFICATIONS`. Если пользователь отказал, переключатель возвращается в выключенное
состояние. Напоминание срабатывает ежедневно в выбранное время; после срабатывания работа
сама планирует следующий день. Системы с жёсткой экономией батареи (некоторые оболочки
производителей) могут сдвигать время срабатывания на несколько минут — это ограничение WorkManager.

## Известные ограничения и планы

- Все строки интерфейса написаны прямо в Compose (только русский язык) — следующий шаг: вынести в `strings.xml`.
- Дата «сегодня» определяется в момент подсчёта; при смене суток с открытым приложением статистика обновится после следующего изменения данных.
- Инструментальные (UI) тесты не написаны.
