# ТЗ-разбор: Трекер привычек

## 1. Цель
Мобильное приложение для Android, помогающее формировать полезные привычки: пользователь ведёт список
привычек, ежедневно отмечает выполнение, видит серию дней подряд и получает напоминания.

## 2. Целевая аудитория
Люди, которые хотят выработать регулярные действия (спорт, чтение, вода, сон). Главный сценарий —
открыть приложение и за пару секунд отметить привычку.

## 3. Функциональные требования (из ТЗ)
| ID | Требование |
|----|-----------|
| F1 | CRUD привычек: создать, просмотреть, изменить, удалить |
| F2 | Отметка выполнения привычки за день |
| F3 | Streak-счётчик (текущая серия дней подряд) |
| F4 | Хранение в локальной БД (Room), данные сохраняются между запусками |
| F5 | Ежедневные уведомления-напоминания |

Дополнительно (сверх минимума, для полноты): лучшая серия, процент выполнения за 30 дней, календарь за 28 дней
с возможностью исправить отметку.

## 4. Нефункциональные требования
| ID | Требование | Как закрыто |
|----|-----------|-------------|
| N1 | Обработка ошибок | Валидация формы; сбои БД → Snackbar; `catch` во Flow |
| N2 | Пустые состояния | Пустой список с подсказкой и кнопкой действия |
| N3 | Локальное хранение | Room, без сети; приложение работает офлайн |
| N4 | Состояние загрузки | Индикатор, пока данные читаются |
| N5 | Тёмная тема | Две цветовые схемы Material 3 |

| US4 | Как пользователь, я хочу видеть серию дней подряд, чтобы мотивироваться её не прерывать | Must |
| US5 | Как пользователь, я хочу изменить или удалить привычку (с подтверждением) | Must |
| US6 | Как пользователь, я хочу получать ежедневное напоминание в выбранное время | Must |

## 6. Критерии приёмки
- **US1:** пустое название не сохраняется, показывается ошибка; название длиннее 40 символов отклоняется; после сохранения привычка видна в списке.
- **US3:** нажатие на чекбокс ставит/снимает отметку за сегодня, счётчик «выполнено N из M» обновляется сразу.
- **US4:** если выполнено сегодня и 2 предыдущих дня — серия 3. Если сегодня ещё не выполнено, а вчера и позавчера выполнено — серия 2. Если пропущен вчерашний день и сегодня не выполнено — серия 0.
- **US5:** удаление требует подтверждения; вместе с привычкой удаляется вся её история; запланированное напоминание отменяется.
- **US6:** на Android 13+ запрашивается разрешение; при отказе переключатель выключается; уведомление приходит в выбранное время и открывает приложение.
- **N2:** при пустом списке показан текст и кнопка «Добавить привычку».
- **N3:** после перезапуска приложения все привычки и отметки на месте.

## 8. Модель данных
```
habits(id PK, name, description, reminderEnabled, reminderHour, reminderMinute, createdOnEpochDay)
completions(habitId FK→habits.id ON DELETE CASCADE, epochDay, PRIMARY KEY(habitId, epochDay))
```
Решения:
- Выполнение хранится как «habitId + день», а серия **вычисляется**, а не хранится. Это исключает рассинхрон счётчика и истории и позволяет исправлять пропущенные дни.
- Составной первичный ключ делает повторную отметку за тот же день невозможной (идемпотентность).
- Дата хранится как `epochDay` (Long) — не зависит от часового пояса и не требует TypeConverter.

## 9. Риски
| Риск | Митигация |
|------|-----------|
| Уведомления не приходят (Android 13+, экономия батареи) | Запрос разрешения, WorkManager, описание ограничений в README |
| Ошибки в логике серий на границах дней | Чистая функция + юнит-тесты, включая границу года |
| Смена суток при открытом приложении | Дата берётся при каждом пересчёте; описано в ограничениях |

## 10. Сценарий демонстрации (7 минут)
1. Пустой экран → добавить привычку «Пить воду» с напоминанием (0:45).
2. Добавить ещё две привычки, показать валидацию пустого названия (1:00).
3. Отметить привычки, показать счётчик «N из M» (0:45).
4. Открыть детали: серия, статистика, календарь; исправить пропущенный день и показать пересчёт серии (1:30).
5. Редактирование и удаление с подтверждением (0:45).
6. Тёмная тема, перезапуск приложения — данные на месте (0:45).
7. Архитектура и тесты: показать структуру, запустить `testDebugUnitTest` (1:30).
